# Design brief

Use this brief when a pending choice changes behavior, ownership, persisted
state, the public contract, or a user-facing flow. Skip sections that do not
affect the decision. Link evidence already written in the issue, docs, or a
private plan without republishing private work records.

| Section | What to show |
| --- | --- |
| Outcome | What the user or operator will be able to do, with a concrete scenario. |
| Placement | The capability that owns the rule, its seam, and which callers or storage adapters cross it. |
| Lifecycle | State transitions, authority, durable effects, failure recovery, and compatibility where relevant. |
| Decision | The recommended shape, its trade-off, and the alternatives still open. |
| Verification | The existing or new test seam for each acceptance criterion, plus the headline flow for a feature. |

Use a sequence, state table, or small diagram if the decision depends on
ordering. Ask for decisions at the point they block implementation.
