# Viewer representation qualification

The isolated pilots compare indexed GLB with the current STL viewer input and evaluate visual simplification against independent protected-feature checks. They do not replace original Artifacts, metadata, similarity geometry, viewer derivatives or download behavior.

## Reproduce the checked-in pilots

Use Python 3.14 and Node 24. The checked-in Python development extra and independent browser-tool lock select the evaluated libraries without adding them to application runtime dependencies.

```sh
cd backend
uv sync --extra dev --frozen
uv run --frozen --extra dev pytest -n0 -q tests/integration/scripts/test_viewer_representation_pilot.py tests/integration/scripts/test_viewer_lod_pilot.py
uv run --frozen --extra dev python -m scripts.viewer_representation_pilot --output-dir /absolute/private/export --repeat 1
uv run --frozen --extra dev python -m scripts.viewer_lod_pilot --output /absolute/private/lod.json
cd ../frontend/scripts/viewer-representation-pilot
npm ci --ignore-scripts --no-audit --no-fund
PLAYWRIGHT_SKIP_BROWSER_GC=1 node node_modules/playwright/cli.js install chromium
cd ../..
node --test scripts/viewer-representation-pilot.test.mjs
node scripts/viewer-representation-pilot.mjs --runtime-dir /absolute/checkout/frontend/scripts/viewer-representation-pilot --manifest /absolute/private/export/manifest.json --output /absolute/private/browser --repeat 1
```

The export CLI exits nonzero while retaining its manifest if any admitted native cell fails. Inspect those failures before selecting browser cells: a missing cell is not a successful conversion. Native execution uses the same shared admission and guarded disposable processes as the application. The browser CLI has a global deadline, isolated build/browser scratch and a separate finite cleanup budget. Use an external process-group supervisor for experiments that need a hard whole-harness deadline.

## What the instruments establish

For generated 3MF controls, reference bytes come from the current canonical STL converter. The real Benchy control uses its unchanged original STL, including declared facet normals. Indexed GLB keeps resources and placements; float64 rebasing precedes float32 output packing. A separate high-coordinate control records canonical STL refusal rather than inventing an equivalent baseline.

Browser samples use the latest evaluated Three loaders (0.186.1; the product currently uses 0.182.0), the existing camera helpers, matching material/lights, a fresh context per observation, disabled response caching and alternating representation order. Timings separate download, parse, preparation and first draw through `gl.finish()`. This measures GPU submission completion rather than compositor presentation. Readback and independent geometry/pixel comparisons are excluded from those intervals.

CPU memory counts unique retained geometry/input ArrayBuffers; it does not establish peak JS heap. WebGL buffer allocation instrumentation counts actual live buffer storage; it does not establish total physical VRAM. Keep these scopes attached to any quoted result. Combined native RSS includes parsing, candidate export and reference conversion and cannot be assigned exclusively to either format.

Quality comparisons retain triangle multiplicity, effective winding, source-space positions, normals, source bounds, full RGBA differences and foreground coverage. Equal empty renders fail qualification. LOD checks component topology, border profiles, analytic holes, creases, thickness and remote small parts independently of requested reduction. Bidirectional finite surface samples measure distances to triangle interiors; they are not a Hausdorff guarantee. Invalid native candidates remain explicit failed rows, with attained counts; no degenerate-face cleanup or original-mesh fallback converts them into a pass. Canonical source fingerprints are recomputed before and after each simplification.

## Current evidence

The pilot is complete with **no automatic production adoption**. [ADR-0014](../adr/0014-viewer-representation.md) records the decision, measurement tables and conditions for reconsideration. This is a qualified rejection of the evaluated candidates, not a claim that GLB or LOD cannot work.

The final performance series contains 800 successful browser loads: four cells, two representations and 100 observations per representation, with no excluded failures. Independent full geometry/pixel checks run on trial zero. All four cells pass the declared visual policy, including actual GPU instancing. Software rendering, loopback transfer, latest standalone loaders and the unchanged product camera/material make this a bounded experiment rather than a hardware-GPU or full product-flow latency guarantee. The instanced candidate has a 778.6 ms outlier; it remains in the reported range and standard deviation.

A real 225,706-facet Benchy indexed export was refused by the unchanged native resource envelope, including after reducing index-key workspace to float32. That refused cell remains explicit. The direct converter test proves geometry/declared-normal fidelity when evaluated outside that shared budget; it does not turn the refused admitted experiment into a successful production conversion.

Nine additional private real-model controls and their observed refusals are recorded in the ADR. Eight successful browser loads qualify three of four exported pairs against the declared pixel policy; no model bytes or paths are published. These single observations are quality controls rather than latency evidence.

The bounded Fast-Simplification 0.2.0 experiment requested 50% and 80% reductions. Sharp-cube and tiny-component candidates contained degenerate triangles. Torus candidates retained 1,440 of 1,536 faces despite requesting 768 and 307. Requested reduction must never be reported as achieved.

The evaluated browser tool versions are Three 0.186.1, Playwright 1.63.0 and Vite 8.3.2. Meshoptimizer 1.3.0 passed the ten declared analytic quality checks after correcting a Float32 boundary-comparison false positive; attained counts still differ from requested counts on the torus. glTF-Transform 4.5.1 produced a 26,280-byte GPU-instanced control from the 242,664-byte shared-node control. The final browser experiment confirms one actual draw, all 24,576 triangles, matching geometry/pixels and 131,792 bytes of live WebGL buffers. The maintained `instance({min: 5})` transform was evaluated only on positive translation placements; affine shear and mixed reflected placements were not qualified through that transform.

A valid 3MF affine shear is preserved numerically in the pilot GLB node matrix, but that matrix violates the glTF node constraint: node matrices must be decomposable to translation, rotation and scale, excluding shear. The current GLTFLoader decomposition consequently cannot retain that shape. This is an invalid candidate export, not a Three loader defect. See the [glTF transformation contract](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc#transformations). The current canonical STL retains all eight analytically expected cube corners and bounds `[[0,0,0],[30,20,20]]`. The browser candidate differs by 5.513554 mm in source bounds, leaves all twelve reference triangles unmatched and changes 13,170 foreground pixels. This is an observed candidate correctness failure rather than a parser refusal or inferred performance risk. A faster load cannot qualify a geometrically different model.

## Validation record

The 37 behaviour rows above are covered by 60 Python pilot cases, 16 Node cases and the new CI contract case. Four focused CI contract tests were executed in total, giving 80 distinct passing cases including three existing regressions. Python export validation ran as 15 cases plus the independently added shear case; LOD ran as 44 cases. Sixteen distinct Node cases are qualified across focused runs against real Chromium where required. Sixteen existing test-hygiene checks also pass (96 distinct cases across these focused selections). Scoped Ruff, Pyright, TypeScript, oxlint and formatting checks accompany normal PR CI. No local full-suite or Deep CI result is implied by these numbers.

Additional Meshoptimizer and glTF-Transform probes use the same source/quality controls but are exploratory experiments outside the normal CI contract. Their API settings, observed counts and precision limitations are recorded in the ADR. They are not runtime adapters or production-safe fallbacks.
