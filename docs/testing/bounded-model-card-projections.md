# Bounded Model card projections

SQLite can retain ANALYZE statistics from a small catalog after an import grows it. The ORM many-to-many tag loader joined the parent Model table again, and chose full scans for a single requested card. Removing that parent join alone still allowed a scan of the growing link table. Card projection now fetches links and labels in batches; SQLite uses the existing composite primary-key index explicitly. Other engines use the equivalent portable keyed SQLAlchemy query.

The same regression exposed similarity annotations joining the Model catalog before proving a candidate existed. Endpoint visibility and current-source checks now use primary-key scalar lookups. Their EDIT boundary, live/purge rules, source hashes, lineage and algorithm versions remain intact. The regression installs the real annotation provider and also rejects Model catalog scans in EXPLAIN, outside the VM counter; an empty-candidate shortcut on one SQLite build can no longer conceal the planned scan.

Identity lookup, offset browsing and cursor browsing suppress the automatic tag loader for their bounded Model batches. Detail relationships remain available normally. Sorted labels, empty tag lists, visibility checks and cursor ordering retain their existing behavior. No schema or API shape changes are needed. The SQLite access path depends on the existing `model_tags` composite primary-key index, whose name is fixed by that table's current schema.
