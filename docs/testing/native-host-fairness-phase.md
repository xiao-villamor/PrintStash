# Native fairness needs a serial host measurement

The native fairness scenario claims the vault's whole physical native budget, keeps six interactive arrivals pending, and requires both full-capacity backfills and every accepted upload to finish. Each other pytest worker creates a separate vault/pool. Its native descendants consume the same host CPU/RAM without participating in this scenario's admission accounting. Running the measurement inside xdist work-stealing therefore does not give the host budget the scenario claims.

Mark the scenario `native_host`, include it in the mandatory serial resource phase, and exclude it from the parallel ordinary phase. Both compatibility phases must succeed. Backend branch coverage still measures the scenario through `--cov --cov-append` before the unchanged coverage gate. No workflow job becomes optional, no deadline/floor changes, and no production code changes. The headline remains real DBOS, uploads, native children and derivative publication. This changes test allocation, not the scheduler's guarantees.

Bounded observation alone did not resolve this. External host contention is an uncontrolled premise, not a fully quantified attribution of every missed second. GitHub Deep CI must still establish the final measured result.

A bounded local cProfile diagnostic completed the scenario (16 uploads, both backfills, whole-budget admission) but did not reproduce the coverage deadline failure. Its instrumentation changed timing and its multithread cumulative call times are unsuitable for full cost attribution.
