# Viewer STL staged publication

Authorized viewer misses persist durable demand and share one logical conversion.
Demand reuses the request Session and finishes its reads before commit and the
work hint, so concurrent misses do not retain nested pool connections.

The worker writes a bounded staged STL. Its fixed-size manifest contains size and
SHA256. The parent verifies an open regular-file descriptor and publishes that
same stream without a whole-file byte buffer. Output/source identity, published
size and current attempt authority must still hold before READY. Rejected outputs
retain pending storage ownership for the existing recovery path.

Source preparation includes the 256 MiB output ceiling independently of compressed
input size. Preparation and disk reservations stay held through publication. Native credits
are released after supervised process exit and descendant cleanup, so slow storage
does not retain compute admission. Recipe 3 adds exact binary STL framing and
chunked float32 representability checks; valid conversions keep their bytes and
coordinates, and originals remain unchanged. Previous viewer recipes rebuild on
demand. The publication reader preserves
ordinary BinaryIO read semantics, with cooperative checkpoints; production hash,
copy and local storage reads use bounded chunks. File-backed remote multipart
pread bypasses those read checkpoints and follows its storage owner's lifecycle.
