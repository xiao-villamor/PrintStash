# Backup recovery regression jobs

A successful archive creation is not proof of recovery. The local compatibility
jobs boot the actual released image, import every supported Artifact under that
release's `testdata/`, then download a real backup through the HTTP API. They keep
the archive plus an independent catalog of Model IDs/names and original Artifact
IDs, filenames, sizes and SHA-256 hashes. The producer image digest is recorded.

Fixtures stay local. There are no release uploads or remote artifact writes.
The baseline is 0.14.0; earlier releases are not covered by this fixture series.

## Create a historical fixture

Requires Docker, the release's Git tag, and the backend virtualenv with `httpx`.
The optional `PRINTSTASH_BACKUP_PYTHON` names another Python with `httpx` installed.
From the repository root:

```bash
bash scripts/create-demo-backup.sh 0.14.0 /path/to/local/backup-fixtures
```

The job uses `ghcr.io/xiao-villamor/printstash:0.14.0` and `git archive v0.14.0
testdata`. It verifies the reported application version, imports all STL, 3MF,
G-code and binary G-code fixtures, verifies the archive, and restores it into a
second, empty Docker volume. It compares every original Artifact byte-for-byte,
restarts the restored container, compares again, and creates another backup.
Only a successful recovery earns the final `0.14.0/` directory. Failed runs remain
under `.building-*` for diagnosis. Existing version directories are never replaced;
a per-version lock prevents competing producers.

**Demo credentials only:** the generated admin is `backup-demo`, password
`DemoBackupOnly123!`, with the explicitly fake encryption key `key`. The metadata
records this demo key. Never use these fixtures or credentials as a real instance.

**The original secrets key is part of recovery.** Current archives include the
application database and managed objects, but not the external secrets key. A
fresh-volume restore requires the original `VAULT_SECRETS_KEY` or
`/data/db/.printstash-secrets-key`, as described in [deployment](deployment.md).
Without it, encrypted settings can prevent the restored application restarting.
The test supplies the producer's demo key to the recovery container; it does not
remove credentials, rewrite the database, disable encryption, or stub restore.

## Check a candidate against retained backups

Build the candidate image from the intended release code, then run:

```bash
bash scripts/check-backup-compatibility.sh \
  printstash:0.14.1-candidate 0.14.1 /path/to/local/backup-fixtures
```

The candidate must actually report version `0.14.1`; an image tag alone is not
proof of its version. The job requires a fixture for every locally known stable
release tag from `v0.14.0` up to (but excluding) the candidate. Fetch release tags
before running. Missing archives, mismatched checksums, failed Jobs, HTTP errors,
wrong versions, changed catalog entries/bytes, restart failures and failure to
create a subsequent backup all fail the job. No fixture is regenerated by the
candidate. An initial `0.14.0` self-check is also supported.

This remains a local gate until fixture publication is authorized; CI cannot
access local-only historical files. The ZIP-inspection restore regression is
also exercised in the regular backend E2E lane and the required browser smoke.

## Run the backup regression suite

Run backend tests as the normal workspace user. Root bypasses filesystem
permissions and invalidates the backup-deletion permission-denial test; do not
weaken that assertion to accommodate a privileged test runner.

```bash
cd backend
./scripts/test.sh full tests/unit/modules/backups \
  tests/integration/modules/backups tests/integration/api/v1/test_backup.py \
  tests/e2e/test_backup.py tests/e2e/test_backup_runs.py \
  tests/e2e/test_postgres_backup.py tests/e2e/test_remote_backup.py \
  tests/contract/modules/backups -n 0 -q
```

This includes the real PostgreSQL, S3-compatible, SFTP and WebDAV recovery cases.
Missing service prerequisites fail the selected lane rather than skipping it.
The browser recovery flow is `frontend/tests/e2e-real/backup-recovery.spec.ts`.
