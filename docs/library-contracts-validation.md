# Library contracts validation

Base `710e4eb7`; shared `refactor/library-navigation-contracts` worktree.

Browse: `GET /api/v1/models/browse`, ModelFilters, view=all|multipart, ModelSort, limit=1..100, cursor. Response `{items:[{kind:model,model:ModelListItem}|{kind:multipart,multipart:MultipartModelListItem}],next_cursor,total,browse_revision,authorization_revision}`. Total counts combined cards. Everything preserves independent member Model cards. Multipart own collection/name+description/tags/favorite predicates are independent; structured artifact/history/printer/similarity filters require a readable live matching member. Date/name sort own fields; Model-specific metrics are null for Multipart. Null last for both directions, kind/id ascending ties. ASCII folding only, Unicode preserved with SQLite BINARY/PostgreSQL C ordering.

Revision-check before/after full read composition detects concurrent commits. Cursor signed and bound to complete normalized filter/view/sort/page-size/caller authorization context and revision. `400 browse_cursor_invalid` rejects tampering/rebinding; `409 browse_refresh_required` requires rebuilding from page one. Events only prompt validation.

Writer inventory: transactional database INSERT/UPDATE/DELETE triggers cover models, multipart_models, multipart_parts, multipart_model_choices, collections, tags, model_tags, collection_tags, file_tags, multipart_model_tags, model_stars, multipart_model_stars, files, metadata, print_jobs, printer_files, printers, documents, collection_permissions, users, model_provenance_sources, model_provenance_fields, model_source_covers, similarity_candidates, similarity_review_decisions, search_passages, search_lexical_postings, search_lexical_terms, search_lexical_state, index_generations, user_search_preferences, vault_generations. Singleton epoch + integer counter changes in writer transaction; rollback leaves revision unchanged. Registry includes ORM, bulk SQL and background writers by affected table. Missing revision fails closed.

Conditional edits expose required edit_version integer initially 1 on Model/Multipart/Document read DTOs. ETags `"model-{id}-v{n}"`, `"multipart-{id}-v{n}"`, `"document-{id}-v{n}"`. Supported first-party clients send `X-PrintStash-Edit-Contract: conditional-v1` plus If-Match. Missing precondition=>428 edit_precondition_required; stale=>412 edit_conflict; unknown contract=>400 edit_contract_invalid. Legacy missing-header requests remain compatible and advance versions; legacy writers are explicitly unprotected against stale overwrites. Metadata field changes, including direct/bulk writers, advance versions; background thumbnails do not.

Thumbnail arrivals: `GET /api/v1/models/browse/thumbnails` accepts 1–24 repeated positive `model_id` parameters (raw request bound), deduplicates preserving requested order, and returns required `{items:[{model_id,thumbnail_url:string|null}],authorization_revision}`. Missing/trashed/inaccessible Models are omitted, including Models in trashed folders for administrators. The thumbnail owner builds canonical versioned URLs; card hydration and pagination are not invoked. Four owner SELECTs cover revision, current actor, bounded Models, revision. Routine catalog changes are allowed; an authorization change inside the read fails `409 browse_refresh_required`. Clients compare the returned authorization revision with their displayed page and discard private presentation on mismatch/401/403; otherwise patch only matching existing thumbnail URLs.

## Supported client and command boundary

The supported-client contract requires every migrated first-party metadata editor to opt into conditional-v1; frontend qualification must verify that coverage before claiming protection across those surfaces. Any client which omits both contract and precondition remains a legacy, unprotected writer; its writes still advance versions so a supported client's draft conflicts. Versions are monotonic, not consecutive: one save can perform a CAS reservation and multiple metadata/child writes. Use the returned server version/ETag; never predict the next value.

Conditional endpoints: Model PATCH; provenance override PATCH; source cover PUT/DELETE; Multipart PATCH, PUT aggregate, PUT parts, PUT tags, PUT uploaded cover, DELETE uploaded cover; Document PUT. Source cover CAS is additional to its existing exact ownership receipt conflict checks. Model batch move/tags accept optional `expected_versions` mapping Model IDs to positive integers. conditional-v1 requires exactly all selected IDs; explicit maps are enforced even without the header. Extra IDs reject400, missing IDs reject428. Move/tag replies use additive ModelEditBatchResult (ModelBatchResult plus required succeeded_versions: dict[str,int]); delete replies retain ModelBatchResult. Success versions are captured after flush and before commit while the transaction owns those rows, so later Undo can use that exact acknowledgement without a racing read. Stale entities are reported in ModelEditBatchResult.failed as `{model_id,reason:"edit_conflict"}` while current peers succeed. Permission/missing/destination preflight retains whole-request errors; refreshed account/session or aggregate-role failures during claims also abort and roll back the batch. Claim revalidates current active/auth_version/admin authority inside the write window instead of trusting the authentication identity map. Lifecycle trash/restore/purge/delete, stars, Artifact revision metadata, print history, and document image assets retain their own domain commands. New Model/Multipart/Document creation has no existing draft to compare; guide body edits use Document's own version. No claim that every lifecycle/action command is a metadata editor.

Physical restore remains an explicit conditional-edit boundary: archived integer edit_version values can be reused after a database restore. Epoch renewal invalidates browse/authorization caches on online revalidation but does not bind existing entity ETags to a restore incarnation. Conditional draft protection across physical restore is unresolved; no change to ETag formats is included here.

## Authority and dependency scope

`GET /api/v1/models/browse/revision` is authenticated and reads `{browse_revision,authorization_revision}` together without hydration. Collection grants inherit via the existing materialized path/RBAC owner; triggers on collections and collection_permissions catch grant, tree, root/folder and trash changes. The separate authorization counter also observes every users write (active/admin/auth_version/account changes) and Model/Multipart/Document collection moves; live status changes for Model/Document bump it. Scope is conservative and global: another user's grant or a collection rename can invalidate private caches. Routine stars/name/description/thumbnail edits change only browse authority. Both counters are transactional and include the same random database-incarnation epoch. Missing authority fails closed. Physical restore renews the epoch in the privately upgraded snapshot's existing marker transaction before publication; both stamps change even if archived counters collide. The marker and epoch commit or roll back together. Forward recovery after a proven active swap preserves that published epoch. A page checks both values after all bounded projection queries.

Access-token authority already depends on persisted users.auth_version and is_active. Logout/session invalidation writes users and therefore bumps authorization authority; online revoked callers get401 (or permission403) and the client clears private presentation. Refresh rotation/API-key revocation affect future credential issuance, not the already-issued bearer access token contract; they do not pretend to revoke existing access rights. No instant/offline revocation guarantee: clients must revalidate online on focus/reconnect and permission events, discard private caches when authorization changes, and honor401/403.

The trigger inventory reflects SQL readers: base Models/Multipart/composition, collection labels/tree/ACL, tags, favorites, Artifacts and extracted Metadata, print/printer state, guide Documents, similarity review, provenance/cover state, search passages/lexical postings/terms/generations and user search preferences. It excludes unrelated filament/session/audit/job-ledger writes. SQLite triggers execute per affected row; PostgreSQL catalog triggers execute once per statement. PostgreSQL transactions which touch this catalog contend on the authoritative singleton, intentionally providing a committed revision rather than a timestamp/keyset pseudo-snapshot. The immutable versioned DDL helper serves both fresh create_all and the autogenerated migration; future trigger changes require a new version/migration.

## Database copy publication boundary

Portable export and database transfer copy exact durable row facts. A source without the required LibraryRevision singleton is rejected as `database_transfer_source_authority_missing` before destination schema creation or data publication, including preview; it is never repaired by bootstrap installation. An unused bootstrap singleton (`id=1`, both counters zero) is permitted in an otherwise empty target; an already-used empty target with a nonzero counter remains rejected. The owner removes only its v1 trigger contract and bootstrap row during the admitted atomic destination copy, verifies row proofs, and reinstalls the same writer guards before publication. PostgreSQL restore already holds ACCESS EXCLUSIVE locks over all expected tables; SQLite export writes an unpublished private snapshot. Failure rolls back PostgreSQL trigger removal and destination changes. Other trigger owners are not disabled.

A normal SQLite→PostgreSQL transfer retains the source incarnation and edit versions; search rematerialization after the verified copy can legitimately advance browse counters. Portable export retains exact authority and metadata versions. Backup restore privately upgrades that exported snapshot, renews its epoch with the marker, then publishes it through the existing SQLite online copy or locked PostgreSQL replacement. That explicit restore renewal prevents browse/access authority reuse; it does not expand integer entity ETag protection across physical restore.
