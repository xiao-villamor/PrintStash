# M9 reusable storage connection editing

Status: active prerequisite to M9 closure. M10 static-delivery work at `8ec882b2`
is preserved, not counted as M10 acceptance; unfinished compatibility cleanup is
shelved until M9 closes.

Connection PATCH currently accepts any previously opened form and returns a fresh
read after committing. There is no captured editing base, so credential/config or
backup-policy edits can overwrite another administrator's changes. Add an
independent version and incarnation identity, pair reads with database history,
and atomically claim the version before validating/applying edits. Preserve
credential omission, target-in-use restrictions and legacy external clients.
Legacy writes advance the same version; restored history/recreated rows reject
stale bases. Capture the acknowledgement inside the write transaction.

This is the connection contract; external Library source edits are the next
separate aggregate. Neither is protected by the global vault config version.
Rollback UI/header adoption together; retain additive schema and safety gates.

## Backend contract checkpoint

Autogenerated migration `46d9d9f875bc` adds exactly two connection columns against
`c9852ff533ee`. Its amendment supplies historical incarnation identities, removes
the temporary default through a frozen SQLite batch definition, and installs
immutable edit triggers on both supported databases. New rows get UUID identities;
reads bind those identities and the database epoch in the same SELECT. Claims
recheck live administrator authority while holding the write lock. Legacy writers
advance versions, but remain unprotected unless they supply preconditions.

  required a counter increment of exactly one; the contract requires advancement.
  It now asserts directly that a rejected transaction leaves the base unchanged,
  followed by an accepted advancing receipt. Ruff also caught a duplicate test
  class name shadowing existing cases; the conditional group was renamed before
  final qualification so those cases run again.

  This includes concurrent writers and five authority-retirement variants per

- SQLite/PostgreSQL migration lifecycle and offline SQL: four passed, 62.75 s.
  Encrypted secrets and configuration survive upgrade/downgrade/upgrade.
- Chain/model convergence: one passed, four deselected, 45.52 s.
