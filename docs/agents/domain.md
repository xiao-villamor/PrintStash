# Domain documentation

PrintStash has one domain context. Read the root [CONTEXT.md](../../CONTEXT.md)
for canonical terms and relationships. Use those terms in code, tests, and
issue contracts.

Read the maintained guide for the affected capability and the code that
implements it. The [architecture guide](../wiki/Architecture.md) and
[engineering routes](../../AGENTS.md#engineering-guidance) point to current
ownership and boundaries. [DESIGN.md](../../DESIGN.md) owns visual and
interaction conventions. [Provider support](../provider-support.md) records
the level of support users can rely on.

Read relevant decision records if present. For a hard-to-reverse choice with
real alternatives, use [domain-modeling](../../.agents/skills/domain-modeling/SKILL.md)
to capture the rationale and link the owning guide. Agree on the durable home
before creating a new public document, and allowlist each approved path in
`.gitignore`. Keep working plans and discussion notes under ignored `reports/`.
