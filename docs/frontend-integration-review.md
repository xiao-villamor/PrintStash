## Concrete findings

**Resolved by coordinator/feature integration: share-token error recovery.** The original local effect retained the denied token's error after successful navigation to a valid token. Current complete route and query-owner reinspection confirms a token-keyed QueryClient scope, signal propagation, teardown clearing, and rendering derived from the current token query; confirmed errors hide previously cached private capability data. Scoped test reads cover denied→valid client-side navigation, held obsolete-token retirement, private-cache independence, confirmed revocation and temporary-error retry (`pages/__tests__/share.test.tsx:160–286`). The real headline uses browser-history token replacement and actual `request.allHeaders()` to assert Cookie and Authorization absent (`tests/e2e-real/share.spec.ts:54–81`). Feature-worker-reported serial qualification was14 unit cases in10.63s and1 real headline in16.9s (test13.9s), after the shared-host quiet window. I did not rerun those frontend gates and do not claim complete viewer coverage.

**Open: OIDC config ownership and held-load drafts.** The OIDC card loads the same vault configuration into effect-owned component state, independently of other config consumers. Advanced mapping fields remain enabled during loading (`disabled={saving}`), while the eventual load completion replaces the entire draft. A user who types in those advanced fields before the initial read settles can lose that input. Source tracing identifies the publication path; no executed held-read reproduction is claimed. Existing tests do not cover that sequence. The public migration plan's I9 and every-remote-read-owner criterion therefore remain unqualified for this surface. No frontend edit or new mutation/version protocol is included in this audit.

**Resolved by coordinator integration: maintenance read ownership and late publication.** FleetMaintenancePanel in fleet-panels.tsx:753–776 stores windows/logs in component state. Its load() launches windows and log requests for each printer and applies both result arrays without cancellation or generation checks. A printers-prop change launches a new batch; an earlier batch can settle later and overwrite newer results. The coordinator subsequently replaced this block with per-printer maintenance Query owners. Current source reinspection covered features/printers/queries.ts:1–113 and fleet-panels.tsx:730–825: removed IDs have no displayed observer data, reads receive Query signals, and authority changes suppress private presentation. Deferred removed-printer completion, shared reads, drafts and partial failures are asserted in components/__tests__/fleet-panels.test.tsx:505–650. Coordinator-reported qualification is 102 cases across five files plus 32 cases after final read-count assertions, as recorded in frontend-state-validation.md. I did not rerun that frontend gate. The whole fleet component remains outside this partial read.

**Fixed; extension gates qualified: capture connection binding.** Printables, MakerWorld and Thingiverse capture branches snapshot `authorization` before provider-link/download awaits, but later read mutable `connectedConfig.vault` when issuing `captureRichFiles`. `importBusy` disables only the capture button; Edit remains available. A connection switch while a provider download is held can therefore pair the previous credential with the new vault URL. Disconnect can similarly retire globals while an older continuation still reads them. The deferred Thingiverse download/vault-switch DOM regression executed RED, observing a synthetic vault A credential sent to synthetic vault B, then passed with the frozen operation owner. Popup, core and capture transport now preserve the original normalized vault/config/credential, retire work on connection changes and guard all publication/finally paths. Native installed-popup/loopback HTTP qualification also passed. This is synthetic boundary evidence, not a live-server exploit claim. Exact files and complete qualification are recorded in [extension-capture-validation.md](extension-capture-validation.md).

**Fixed; extension gates qualified: invalid login body.** `core.ts` vaultLogin maps failed JSON decoding to null, then dereferences `loginBody.access_token` without guarding null. A successful HTTP status with malformed JSON or JSON null raises TypeError instead of the intended “did not return an access token” domain error. Malformed JSON and JSON null cases executed RED and now assert the intended missing-access-token error. Full extension suite and all three browser builds passed; the whole core test file was not manually audited.
